GPU clock caps on the two-Spark cluster

What a graphics-clock cap (nvidia-smi -lgc 0,<MHz>) costs in time and throughput, and what it saves in energy, heat and fan wear. Every run does the same fixed work on DeepSeek-V4.1-Flash-1017 (EXL3, TensorFold, both Sparks). Hover any chart for exact values; every chart downloads as PNG, SVG or CSV.

Sessions

Pooled view: the 10-30 night ran only uncapped, 2,500, 2,200 and 1,900 MHz, with slightly different cool-down targets (57 / 58 °C against 55 / 53 °C). Its 1,900 MHz runs were faster (about 1,507 s against 1,525 s), which makes the pooled 2,200 → 1,900 MHz step look cheaper than either session shows. Compare arms within one session for the step sizes.

Keep the 1,900 MHz cap. On 2026-10-31 it did the same work in 1,525 s against 1,468 s uncapped (103.9%) for 129.3 Wh against 170.0 Wh (76.1%), and it kept the head fan off its top speed for the whole run. Below 1,900 MHz the energy per run stops falling while the time keeps rising, so the original 1,800 MHz recommendation does not hold: it adds 24 s per run for 2.2 Wh, inside 1,900 MHz's own run-to-run spread.

The cap is installed on both nodes as gpu-clock-cap.service and set at every boot. Prefill is the phase the cap slows most: 1,852 against 2,025 prompt tok/s (91.4%).

How it was measured

  • The work. Each run sends 20 long prefill requests, then 50 requests one at a time, then 70 requests two at a time, to one server process spanning both Sparks. The arm order rotates each round. Between runs the driver waits at least 180 s and until both GPUs are back to their cool-down target.
  • Sessions. 2026-10-30 night: uncapped, 2,500, 2,200 and 1,900 MHz, 3 runs each, targets 57 / 58 °C. 2026-10-31: all seven arms, 3 runs each, one server process, targets 55 / 53 °C (2,500 and 2,200 MHz ran last, as a gap fill).
  • Power. Two Kasa EP25 smart plugs, one per node, read through Home Assistant at about 5 s. Energy per run is the integral of both plugs over the run.
  • GPU clock, temperature and power. NVIDIA DCGM exporter, read from Prometheus at a 15 s step.
  • Fans. nvfanread on the head node; the worker does not have it yet (evanwtf/dgx-spark-fan-override#14).
  • Inlet air. An indoor weather-station sensor next to the cluster; it records only on change.

What this does not show

  • Coding-agent wall time. This is a fixed synthetic load; an agent that re-reads long contexts leans on prefill, the phase the cap slows most.
  • Other stacks, other concurrency, or one Spark.
  • Confidence intervals. Three runs per arm give a mean and a range.
  • The worker's fan, and fan time during cool-downs (uncapped runs end hotter, so the chart understates the gap).
