## What this is a lead for

1. **ds4 PRs 953/954** — GLM-5.3 Flash +3.5% prefill and DeepSeek-V4 Flash +4% prefill / +6.5% decode, stated for **M5 TensorOps**. That is our engine and our chip. Check whether they landed, then re-measure.
2. **Ivan’s Qwen3.8-Flash-Next ds4 branch** — still WIP. Same model we already run; the question is whether ds4 can serve it without the Unsloth MTP graph.
3. **mlx-serve 26.9.1 + mixed 4/8-bit Qwen3.8** — 1M context, 92.4 GB, NIAH at 600k, MTP **110 tok/s greedy depth=5** on M5 Max. QSA KV leak that OOM’d 128 GB is the trap. OpenCode2 was the client at ~100k context (47.4 tok/s decode, not greedy).
4. **MTPLX PR 391** — 65.5 tok/s at 256k on **M5 Max 128 GB**, Spangler long-context prefill kernels included. Decode vs mlx-serve is the claim; prefill still mlx-serve. Agent wall time is unmeasured.
5. **Q2 imatrix on 128 GB via DwarfStar** — Ivan’s quality claim, no numbers.
6. **macOS 27 beta GPU throttle in High Power** — possible confound if any machine is on the beta.

Nothing here is a result until we run it. The 110 tok/s and 65.5 tok/s figures are decode rates on coding prompts, which this project has already shown do not predict agent wall time.
