## Findings that still hold

Each is one line. The numbers are from that date's run, not from the current
ledger.

**How wall time works**

- **Wall time ≈ output tokens ÷ generation rate, plus per-turn overhead.** Across
  seven backends, tokens alone correlated r = +0.35 with wall time, rate alone
  r = −0.67, and their ratio r = +0.96.
- **The rate term, isolated.** A ds4 upstream sync (`5be6b6c` to `fdcf3aa`)
  raised decode from 36.8 to 40.6 t/s. Median output tokens held at 2,130 and
  2,120, and the median task fell from 164.4 to 140.9 s.
- **Tokens per second can invert a ranking.** Qwen3.8-Flash-Next `UD-Q3_K_XL`
  decodes slower per token than the 2-bit quant and finished the suite 28.4%
  faster, on all five tasks ([#31](https://github.com/evanwtf/local-llm/issues/31)).
- **A fewer-tokens-therefore-faster result is a sampler hypothesis until the
  samplers match.** llama.cpp took 166% of Ollama's suite time on byte-identical
  Ornith-1.5 weights (870.8 s against 523.1 s). Per-token throughput was equal.
  With `repeat_penalty 1.1` and Ollama's other defaults set, the gap fell to
  +10% and +5%, inside the noise
  ([#28](https://github.com/evanwtf/local-llm/issues/28)).
- **Re-prefill dominates agent wall time on this machine**
  ([#14](https://github.com/evanwtf/local-llm/issues/14)). A decode-rate claim
  does not predict an agent result.

**How many trials a claim needs** ([#23](https://github.com/evanwtf/local-llm/issues/23), `benchmarks/agent/sizing.py`)

- A 3-trial task median carries ±27.9%; a 5-task suite total carries ±12.9%.
  Two suite totals need a gap of about 26% before the difference is real.
- To show a pass rate above 90% at 95% confidence takes 35 consecutive passes.
  One failure costs about twenty more trials.
- Three trials is a screen, not a measurement. Under the bar, write "no
  difference measured".

**Samplers move pass rate, not only wall time** ([#36](https://github.com/evanwtf/local-llm/issues/36), [#37](https://github.com/evanwtf/local-llm/issues/37))

- On Ornith-1.5 `storage-blob-put` under llama.cpp, `top_p 0.90` without a
  repetition penalty passed 7/12; `top_p 0.95` passed 17/18; `top_p 0.90` with
  `repeat_penalty 1.1` passed 6/6. Pin every sampler value on both sides of an
  engine comparison, and vary one at a time.

**Harness and client**

- **The client-backend pair is the unit.** On ds4, Codex and Claude Code were
  indistinguishable (975 s against 982 s over the suite). On
  `qwen3.6:27b-coding-mxfp8` under Ollama, Codex took 163% of Claude Code's time
  (1,699 s against 1,041 s).
- **Three failure signatures:** Claude Code's failures were near misses; Codex
  once left the file unparseable (`1 error`, a collection error); the
  pre-cutover OpenCode "failures" returned the control result unchanged, which
  was the `--dir` bug above.
- **ds4 needs a server restart between trials** for Qwen3.8-Flash-Next. With a
  restart, arm A held 14/15 in each of three trials (42/45); without one it fell
  13, 13, 10. Raising the disk KV budget to 32,768 MB did not reproduce the
  gain, so disk KV is not the cause
  ([#112](https://github.com/evanwtf/local-llm/issues/112),
  [#120](https://github.com/evanwtf/local-llm/issues/120)).
- **ds4's streaming path dropped tool calls.** The `qwen38fnds4shim` cell read
  0/45 because `stream: true` returned an empty turn 11 times in 12. The shim
  requests a non-streaming completion when the request carries tools, and the
  cell went to 36/45 ([#94](https://github.com/evanwtf/local-llm/issues/94)).
- **ds4's MTP at depth 7 did not help an agent.** It raised per-token throughput
  about 10%, the model emitted 33% more tokens, and arm B passed 25/45 against
  arm A's 42/45 under the same restart protocol. ds4's default MTP acceptance
  does not preserve the sampling distribution, so arm B is a differently sampled
  model ([#77](https://github.com/evanwtf/local-llm/issues/77)).

**Memory and offload** ([#33](https://github.com/evanwtf/local-llm/issues/33), [#34](https://github.com/evanwtf/local-llm/issues/34), [#35](https://github.com/evanwtf/local-llm/issues/35))

- **The PLE offload saves nothing.** On unified memory, mmap already makes all
  88 GiB of llama.cpp weights evictable: the physical footprint was about 5 GB
  with or without the PLE tensor pinned to CPU. The 4-bit `-M64` build took 128%
  of the 3-bit suite time (1,276.0 s against 995.1 s).
- **ds4 expert streaming trades memory for time.** It cut resident memory from
  91.0 to 36.7 GiB and took 176% of the resident suite time (1,748.6 s against
  992.8 s), with no change in correctness. Use it only when a model does not
  fit. `--warm-weights` defeats it, and `--warm-weights` off without streaming
  leaves the weights neither resident nor streamed.
- **GLM-5.2 runs streamed, and is not practical.** 196.6 GiB on disk, 30.8 GiB
  resident, about 4 tok/s decode, and 2,585.5 s for the easiest task.
- **The `iogpu.wired_limit_mb=114688` sysctl is load-bearing for ds4 on a
  128 GB Mac.** ds4's 128 GiB-host branch needs a Metal working set of at least
  120 GiB, which a 128 GB Mac never reports (107.52 to 112.00 GiB). Without the
  sysctl, ds4's budget is 75.5 GiB.
- **ds4 requires F16 for its compressor and indexer tensors**, so the GLM-5.3
  BF16-to-Q8 decode win does not transfer to DeepSeek-V4-Flash. The only
  eligible tensor is 1.7% of per-token traffic
  ([#48](https://github.com/evanwtf/local-llm/issues/48)).

**Task design** ([#4](https://github.com/evanwtf/local-llm/issues/4), [#44](https://github.com/evanwtf/local-llm/issues/44), [#45](https://github.com/evanwtf/local-llm/issues/45))

- **Harder tasks cost time, not correctness.** Three harder tasks raised the
  per-task median from 194.6 to 270.6 s at 18/18. `restored_verbatim` was 0/18,
  so the tasks measured problem solving, not recall.
- **"Passes but is worse" is real.** `mbox-quoting-both-halves` added the same
  two `mypy` errors in 5 of 6 trials (a bare `re.Match`), with all tests green.
- **A second repository separates pairs by token inflation.** On a Swift
  target, pairs wrote 1.19 to 2.73 times their Python output, and the gap
  widened on harder tasks. Ruff and mypy lint nothing on Swift, so their `0`
  delta there is an absent gate, not a passing one.
- **The hosted reference took 18% of the local time.** Opus 5 finished the
  suite in 203.4 s against 1,116.2 s for ds4 under Claude Code. Opus wrote the
  target repository, so read its pass rate as contaminated.

**GLM-5.3-Flash** ([#38](https://github.com/evanwtf/local-llm/issues/38), [#41](https://github.com/evanwtf/local-llm/issues/41))

- antirez's GGUF (`glm5-next`) and Unsloth's (`glm5next`) are not
  interchangeable; neither engine reads the other's file. On ds4 with antirez's
  file, every agent turn re-prefilled about 40k tokens at 361 t/s with zero KV
  hits, and Codex rejected its string `"false"` for boolean tool arguments.

## Reader bugs, and the guard for each

- `summarize.py` once counted rows marked with the legacy `confound` and
  `contaminated` keys. Read exclusions through `benchmarks/agent/results.py`
  ([#29](https://github.com/evanwtf/local-llm/issues/29)).
- A timed-out trial has no `passed` key, and readers dropped it from the
  denominator. Use `results.verdict()` and `results.trials()`; never test
  `row["passed"]` directly.
